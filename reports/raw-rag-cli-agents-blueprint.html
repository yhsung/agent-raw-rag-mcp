1 系統總體架構圖：四端增量採集 → 確定性降噪 → 統一 MCP 檢索

四套 CLI 工具各自透過 Hook 或增量游標（Cursor）把新完成的對話回合推入寫入管線；讀取時則統一透過 MCP 工具 raw_rag_search 取得經過時序重排與完整回合展開的 Top-15 記憶。

2 Coding Agent 專屬改造：為什麼要先過一層「確定性降噪器 (Deterministic Sanitizer)」？

在你的機器上，~/.local/share/opencode/opencode.db 高達 3.19 GB，因為 Coding Agent 的原始紀錄有 90% 以上是 Read 檔案全文、grep 列表或長篇編譯輸出。若直接切塊會嚴重稀釋向量檢索精度。我們在不使用 LLM、100% 保留人類與 Agent 對白原文的前提下，對 Tool 紀錄做確定性瘦身：

4 四大工具接線規格與設定檔藍圖

根據你機器上的實際安裝路徑，以下為四套 CLI 工具接入 agent-raw-rag-mcp 的具體設定方式：

1. Claude Code (~/.claude/settings.json) Hook + MCP

利用 Stop Hook 在每輪回答完成時觸發背景增量更新（只讀新增 byte offset），並掛載 MCP Server： 

{
  "hooks": {
    "Stop": [{
      "hooks": [{
        "type": "command",
        "command": "raw-rag-ingest --agent claude --incremental"
      }]
    }]
  },
  "mcpServers": {
    "raw-rag": {
      "command": "raw-rag-mcp"
    }
  }
}
2. Codex CLI (~/.codex/config.toml) notify + MCP

利用 Codex 原生 notify 機制在每輪 Turn 結束時同步 ~/.codex/sessions/**/*.jsonl 尾部區塊： 

# 每輪對話完成自動執行增量切塊與嵌入
notify = ["raw-rag-ingest", "--agent", "codex", "--incremental"]

[mcp_servers.raw_rag]
command = "raw-rag-mcp"
args = []
3. OpenCode (~/.config/opencode/opencode.json) SQLite 游標 + MCP

針對 3.19 GB 的 opencode.db，依 message.time_created > last_cursor 只抽取文字 Part（跳過巨型 Tool output）： 

{
  "mcp": {
    "raw-rag": {
      "type": "local",
      "command": ["raw-rag-mcp"],
      "enabled": true
    }
  }
}
4. Oh My Pi (~/.omp/agent/mcp.json) Standard MCP

僅透過標準 stdio MCP 提供四個工具，不安裝原生工具擴充。增量索引由背景 Daemon 負責；壓縮後可呼叫 mcp__raw_rag_recent 取回最近對話： 

{
  "mcpServers": {
    "raw-rag": {
      "type": "stdio",
      "command": "uvx",
      "args": [
        "--from",
        "/Volumes/Samsung970EVOPlus/dev-projects/agent-raw-rag-mcp",
        "agent-raw-rag-mcp"
      ],
      "env": {
        "HF_HOME": "/Volumes/Samsung980/hf-home/"
      }
    }
  }
}

5 落地實作藍圖：/Volumes/Samsung970EVOPlus/dev-projects/agent-raw-rag-mcp

若要將此設計實作為常駐工具，建議於 /Volumes/Samsung970EVOPlus/dev-projects/agent-raw-rag-mcp 建立以下輕量架構：

模組檔案 核心職責 對應 Litmeb/RAW-RAG 機制
src/parsers/{claude,codex,opencode,omp}.py 讀取四套工具的 JSONL / SQLite，維護增量游標（byte_offset / last_rowid），並執行 Deterministic Sanitizer 剝除長篇 Tool stdout。 對應 _format_conversation 與 _format_message_line。
src/engine/incremental_chunker.py 維護 stable_chunks 與尾部可變 tail_chunks（256 tokens, overlap 32），建立 turn_spans 與日期索引。 直接移植 RAGAdapter.add_incremental_message 與 _build_turn_context。
src/engine/mlx_retriever.py 載入 MLX Qwen3-Embedding-4B 與 Qwen3-Reranker-4B，執行時序過濾 → Dense Top-128 → Rerank Top-15 → 時序升冪重排 → 展開完整對話回合。 移植 _filter_chunks_for_question_date、_selected_chunk_time_sort_key 與 _expand_chunk_to_turns。
src/mcp_server.py 提供標準 stdio MCP 服務（raw_rag_search、raw_rag_ingest、raw_rag_status），一鍵掛載至四大 CLI 工具。 取代原本實驗框架的內部 Reader 呼叫，直接將 _format_context 結果回傳給 CLI Agent。
